# 关键代码讲解

## 1. 为什么向上是 (-1, 0)？

棋盘坐标使用 `(row, col)`，屏幕上方是第 0 行。向上使行号减 1，列号不变。绘制时才换为 `x=列号×格宽`、`y=行号×格宽`。混用行列与 x/y 会导致方向旋转 90 度。

## 2. 为什么从下一格开始扫描？

自己的格子当然有箭头，如果从当前位置检查，会把自己当作阻挡物。先加一次方向向量，再扫描到边界。遇到任何箭头即判定阻挡，无论该箭头朝向哪里。

## 3. 如何避免向上、向左越界？

每次读取格子之前先执行 `0 <= row < rows and 0 <= col < cols`。这样 -1 不会被 Python 解释成最后一行/列。

## 4. 为什么随机关卡一定有解？

先选一组占用位置，暂不确定所有方向。每次挑一个在当前剩余占用中能沿某个方向离开的格子，为它赋予这个方向并从临时占用表删除。最外侧的占用格总能向外离开，所以可以一直进行直到空棋盘。之后按记录顺序操作，每一步前方都没有尚未消除的阻挡物。

最终布局中的某些箭头起初可能被挡住，因为生成过程中排在它前面的箭头会先移除。三个固定关卡存成 JSON，不会在每次重开时变化。

## 5. 求解器为什么不需要回溯？

规则只会删除箭头，不会增加箭头、改变方向或制造新障碍。删除一个当前可移除的箭头不会使其他箭头更难移除。因此可以贪心移除所有当前合法箭头；如果棋盘非空却没有合法操作，就是死局。

## 6. 动画和状态为什么分开？

点击时只记录动画对象；动画期间不接受第二个箭头点击；动画结束调用 `Game.attempt()` 更新一次状态。这样不会一边飞行动画一边重复扣次数，也不会刚显示动画就提前跳到结果界面。重新开始清空动画对象，再创建一局新游戏。

## 7. 提示会不会悄悄改变棋盘？

提示使用 `Board.available()` 找出当前可移除箭头，仅设置高亮和提示次数，不删除箭头。3 秒内重复请求同一提示不会重复计数；使用提示会影响最终星级。

## 8. 测试通过能说明什么？

23 项测试验证了规则、边界、状态和鼠标事件驱动流程，生成算法另外跑了 125 个布局。离屏截图验证本机字体与画面。这些结果不等于其他操作系统也已验证，也不能代替本人实际试玩。
